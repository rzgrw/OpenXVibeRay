# The Agentic Zone: A Design Brief for xrMind + xrSim

## 0. Naming and the one-sentence thesis

**xrMind** is the agent layer: a C++ harness (`xrAgentRuntime`) that instantiates and drives persistent, tool-using `WorldAgent` objects — Claude Code / Codex-pattern agents — that *own the evolution of the off-screen Zone*. **xrSim** is the thin C++ layer: an authoritative coarse **state store** (`xrWorldState`), a **near-player real-time executor** (materialization + behavior trees), and the **materialization boundary** between them. xrMind decides *what the world becomes*; xrSim decides *what the player sees and touches right now*, and coasts on xrMind's last plan in between.

The rest of this brief is opinionated. Where the six fragments and the critique conflict, I resolve it explicitly and say why.

---

## 1. The inversion, stated plainly

**Old (2026-07-05 zone-sim spec):** a deterministic C++ sim (`xrSim`) owns all Zone state — Lotka-Volterra ecology, faction economy, event scheduling — and an LLM acts as an *advisor* whose suggestions the sim may apply.

**New:** invert authority. **LLM agents (xrMind) own the world's evolution.** C++ (xrSim) is demoted to two jobs: (a) a thin authoritative coarse **state store** that is the single source of truth, and (b) a **real-time near-player executor** that materializes coarse state into concrete entities and runs their physics/combat/behavior at 30 Hz. The LLM never computes per-NPC-per-tick anything; the C++ executor never *authors* world change on the strategic path (reconcile is its one write-back).

**What this wins:**
- **Emergent narrative without hand-coded rules.** Faction politics, ecology shifts, economy swings, and named-individual arcs come from a reasoning model, not from equations a designer had to anticipate. This is the whole product bet.
- **Believability that scales with model quality, not engineering hours.** The Zone gets better as the models get better, at zero code cost.
- **A coarse, LLM-legible state model** (~30-60 regions, 8-12 factions, per-(region,species) counts) that is small enough to serialize, snapshot, and fit in an agent's context.

**What it costs (the honest ledger):**
- **Determinism is weaker.** A live run is not reproducible from seed alone — only from *recorded agent tool-calls* (§7). This is the single biggest regression versus the pure-C++ sim.
- **The game is effectively online for its headline feature, and offline is deliberately THIN** (rz, 2026-07-05). When the provider is unreachable, the Zone's strategic *evolution* simply **freezes and coasts on its last authored plan** — the near-player C++ executor keeps running (you can move, fight, loot, survive), but the world stops *changing* until reconnect. We do **not** build a rich offline "second game," and we do **not** stand up a resident on-device LLM to fake it: **local compute — unified memory and GPU — is reserved for the renderer (RT, fidelity) and physics, which use it far better than a local model would.** Offline is a graceful pause of the living world, not a parallel simulation. (§5, §8)
- **Real cost and latency.** Lively play is **$3-8/wall-hour** per player, not the $0.15 an L0-only estimate suggested (§5, resolving the critique's P0). The game must coast and never block.
- **New engineering surface we own:** provider adapters, prompt-cache management, a budget ledger, record/replay, subagent lifecycle. More than calling an SDK — and all of it must be value-returning, never a THROW (Darwin `XRAY_EXCEPTIONS=0`).

## 2. The agent harness (xrMind)

### 2.1 The WorldAgent object

A persistent C++ object, serialized into the xrSim snapshot so it is *the same object across save/load*:

```
WorldAgent {
  agent_id: u32          // stable, never regenerated (mirrors entity-id invariant)
  scope: enum { ZONE, FACTION, REGION, ECOLOGY, NAMED_INDIVIDUAL }
  charter_version: u16   // immutable, versioned system-prompt/identity; a wake pins to it
  memory_ref            // into per-agent persistent memory store
  tool_set             // schema-constrained; a subset of §3's tools by scope
  budget { tokens, latency_ceiling, dollars }
  continuity_state { last_plan, last_situation_hash, subagent_handles, reflection_cursor }
}
```

The defining property vs. a one-shot API call is **continuity**: a WorldAgent lives across a whole 40-hour playthrough, carries forward a summarized memory, and *revises its own prior plan* rather than re-deriving the Zone from scratch.

### 2.2 The reason-act wake loop

`observe → assemble prompt → think → emit tool calls → two-phase validate → apply as intent → feed results back → repeat until commit_plan or budget exhausted → sleep.`

- Prompt = **[charter (cached prefix) + tools (cached) + rolling memory summary (cached per-agent) + volatile observation]**. Prefix caching keeps charter+tools+memory near-free on repeat wakes (verified 0.1× cache-read). **The observation must sit after the last cache breakpoint** — any byte change in the prefix invalidates everything after it.
- Adaptive thinking on (`thinking: {type:"adaptive"}`), effort by scope: ZONE at `high`/`xhigh`, FACTION/ECOLOGY at `medium`/`low`.
- **Cadence is surprise-driven, not clock-driven.** The clock only *permits* a wake; a novelty/stakes threshold (broken precondition, player action outside the last plan, emission, mass die-off) is what *wakes* an agent. A stable Zone hour costs near-zero tokens.

### 2.3 Hierarchy and subagents (orchestrator-worker)

- Exactly **1 persistent ZONE orchestrator**, always resident.
- It spawns FACTION/REGION/ECOLOGY subagents via `spawn_subagent(objective, scoped_observation, output_schema, boundaries)` — the four-field task-packet discipline — with **fresh context** (children never see siblings or the parent's full reasoning).
- Children return **schema-only intents**; the parent does a **deterministic merge** (fixed precedence, tiebreak by agent_id) — no re-reasoning, so parent context never re-inflates.

### 2.4 Memory / reflection (three tiers per agent)

1. **Charter** — frozen identity.
2. **Rolling reflection summary** — after each wake, compress "what changed and why" into ≤~1-2k tokens (self-written, or a cheap Haiku 4.5 / Batch-API summarizer). Keeps context bounded over 40 hours.
3. **Episodic intent log** — stored in the sim (the replay/audit backbone), never resent to the model.

### 2.5 How many are alive — bounded, and re-scoped to the real budget

The critique's P0 correctly caught that `agent-harness`'s "≤8 subagents" and `cadence-cost`'s "3-8 hot regions each with subagents" were the same budget double-counted. **Resolution — one number:**

- **1 ZONE orchestrator** (always resident).
- **≤2-3 concurrent live subagents total** (FACTION/REGION/ECOLOGY combined), not 8, not "8 per hot region." Everything else **coasts on its last committed plan** and is not a live wake.
- **≤16 long-lived NAMED_INDIVIDUAL agents**, LRU-demoted to dormant records when off-screen and quiet — **except** any named individual referenced by an active quest, recent player interaction, or player proximity is **pinned** and exempt from demotion (resolving the critique's P2: LRU is the wrong policy for the entity the player is tracking).
- On lower-end Apple Silicon, scale the concurrent-subagent cap to 1 and lean harder on coasting + the on-device SLM.

This is the difference between an affordable live world and a $12/hour one.

## 3. World-state store + tool API (xrWorldState)

### 3.1 The coarse model

A small, flat, LLM-legible authoritative record — struct-of-arrays, **stable u32 handles (24-bit index + 8-bit generation, never regenerated), fixed-point for everything persisted** (floats live only in the near-player executor and are re-derived on load — this fixed-point firewall is load-bearing for replay determinism, §7):

- ~30-60 **Regions**; 8-12 **Factions** (ledger + relation matrix + owned regions)
- per-(region, species) **PopCohort** COUNTS (not per-NPC)
- per-region **EconIndex** per commodity
- active **Events** (emissions / anomaly blooms / wars, with eta/ttl)
- **PlayerReputation** per faction
- **Individual** roster of NAMED/notable entities only

### 3.2 The tool surface (~20 tools, deliberately small)

**Read (7, idempotent, not logged, return the same bucketed token-budgeted projection the context is built from):** `observe_region`, `query_faction`, `list_events`, `get_roster`, `get_relations`, `observe_economy`, `read_reputation`.

**Write (~15, scarce, clamped, logged, reversible via snapshot):**
- *Faction/territory:* `move_force`, `set_relation`, `set_control`, `declare_event`
- *Ecology:* `adjust_population`, `set_migration`, `seed_population`, `set_breeding`
- *Economy:* `set_price`, `set_supply`, `set_trade_route`
- *Events/narrative:* `spawn_event`, `author_quest`, `set_narrative_beat`, `adjust_reputation`
- *Individuals:* `promote_individual`, `retire_individual` (the coarse↔named boundary)

### 3.3 Validate / apply / rate-limit / stamp — the three-stage gate

Agents never touch memory; C++ (`ToolDispatcher`) is the sole mutator. Every write passes:

1. **Ingest validation** against the snapshot the agent's context was built from — schema/type, handle existence, enum legality, range clamp.
2. **Conservation + rate/quota** — integral per-region-per-day population bounds, hops-per-day force-move budget, ≤1 emission/region/N ticks, relation-delta clamp, intra-batch last-writer-wins. **Rate-limits are the load-bearing anti-cheat:** direction lives in the LLM, RATE lives in C++. An agent physically cannot teleport a faction or wipe a species in one call.
3. **Apply-tick re-validation** at drain time (the async call spanned many ticks; handles may have died). A dangling ref **degrades to the region aggregate or drops-with-feedback, and NEVER reaches a THROW** — this is stability-critical on Darwin.

Rejections return as tool-result values `{ok:false, reason, suggestion}` the model learns from. Every accepted mutation is **stamped into an append-only `ToolLog`** (agent_id, tool, args, seed, ingest_tick, apply_tick, content_hash, model, tier) — the replay/determinism backbone (§7).

**Hard contract (resolving critique P1(b)):** read tools return **guardrail-adjusted** state, never raw-authored. If the agent said "boom" but carrying-capacity capped it, the digest reports the *capped* number, or the agent reasons on a fiction and compounds the lie.

## 4. The materialization boundary

Two authorities must **never both own the same entity at the same time**: the coarse store (counts + notable records) vs. live SoA entities with physics/animation/behavior trees.

- **materialize(region)** — coarse→concrete. Triggered when a region enters the OFFLINE ring (player within K hops or agent-flagged hot). **Single-threaded, region-id-ordered, budget-bounded, trickled** over N ticks (never an army in one frame), off the `materialize` PRNG stream seeded from (region_id, sim_day). Decrements the cohort as it draws (conservation); re-attaches every notable/dormant record **by permanent id first**; places anonymous entities on graph vertices weighted by smart-terrain capacity; seeds each entity's local utility behavior tree from its need vector + the region's current agent-authored objective field.
- **dematerialize + reconcile** — concrete→coarse. Folds survivors back (`cohort.count += survivors`), logs births/deaths/kills, and **promotes anything the player touched**. Reconcile is the *only* writer back to the store on this path.
- **ONLINE⇄OFFLINE** stays the cheap existing `switch_online/switch_offline` proxy attach/detach with asymmetric hysteresis (promote ≤150m, demote >200m) — never a spawn, never a new id.

**Id stability:** notable/dormant records keep permanent ids across any number of cycles; anonymous fauna get ephemeral ids scoped to a materialized lifetime ("a different rat next time" — honest, and fine for wildlife). *No gameplay system may reference an anonymous id across a dematerialize boundary* — the validator catches designer violations.

**Near-player = real-time behavior trees, NOT the LLM.** A materialized blind-dog pack hunts/flees/dies by deterministic utility trees at 30 Hz. Agent decisions reach live entities by **intent redirection, not respawn**: an agent's validated intent compiles to a `PlanOp` that writes a **region-level objective field** (`FactionObjective[region]`, `MigrationHerdTarget[species]`, `SpawnQuota[smart_terrain]`); the live squad's behavior tree reads that field as its goal and re-steers next tick. The executor redirects the existing unit — it never tears it down.

### 4.1 Resolving the critique's P0 cross-fragment conflict (this is the #1 place to keep deterministic scaffold)

The critique is correct: agent cadences (90 s L0 trigger, 4-in-game-hour plan horizon, 30-in-game-min eco tick) are fine for off-screen evolution and **catastrophic on the frame the player is watching**. A bandit squad fighting the player *now* cannot wait 90 s to re-decide whether to flank.

**Invariant, stated as a hard rule:** *No agent decision is ever on the critical path of a frame the player is watching.* Near-player tactical decisions — squad target selection, flank/retreat, pack hunt/flee, day/night hunt clustering — are **100% deterministic C++ utility behavior trees, permanently, with the LLM never in that loop.** We **delete the `agent-harness` "player action wakes the agent" fast-path** that invited the LLM back into the seconds-scale loop. The agent authors *region-level posture* (slow-changing field); the BT owns everything the player sees react in real time.

**Promote-on-player-contact aggressively** (resolving P1(a), the amnesiac-world tell): any entity the player damaged/looted becomes a dormant record with a real id, accepting the roster-growth cost `worldstate-tools` warned about. Over a 100-hour campaign the promoted-record count is bounded by *what the player actually engaged*, which is far smaller than the fear.

## 5. Cadence, cost, coasting, non-blocking

### 5.1 Cadence
- **L0 ZONE:** wall-clock trigger ~90 s (config 60-180 s), early-fire on salience, min 30 s between calls, max 1 in flight. Plan horizon ~120 ticks (~4 in-game hours).
- **L1 FACTION/REGION:** one call per hot region, **capped at 2-3 concurrent total** (§2.5), ~15-40 s wall; quiet factions get zero calls.
- **L2 squad/pack:** ~90% collapsed to deterministic C++; only surprise-flagged units escalate, batched same-kind into one array-output call.

### 5.2 The honest cost envelope (resolving critique P0)

The $0.15/hr figure was **L0-only and silently swapped in-game hours for wall time.** Corrected, with the multi-agent ~15× factor applied explicitly and current pricing (Opus 4.8 $5/$25, Sonnet 5 $3/$15, Haiku 4.5 $1/$5):

- **L0 Opus near the trigger cap:** ~$0.96/wall-hr (not $0.15).
- **Coasting Zone, nothing happening:** ~$0 (surprise-gating).
- **Actively-lively play (emission/war/firefight):** **$3-8/wall-hr per player**, dominated by L1 fan-out — which is *why* the concurrent-subagent cap is 2-3, not 8.

State this range in the spec as the aggregate L0+L1+L2 envelope. **Defer "subscription-covered" as a marketing claim until measured** — it is almost certainly false for lively play.

### 5.3 The rate-limit ceiling is the real binding constraint (not dollars)

The critique is right: 1 L0 + 8 L1 on a 25 s tick ≈ 21.6 req/min/player — subscription plans meter RPM in the tens, so a single player with two hot regions hits **429s before hitting a dollar cap.** Capping concurrent subagents to 2-3 and surprise-gating wakes is the primary mitigation. The wake scheduler paces L0/L1 against a per-plan RPM allowance, not just a token ledger. *(Note: rate limits are the least-documented dimension — validate against actual plan RPM before shipping; the claude-api skill lists "subscription rate-limit mapping" as genuinely underspecified.)*

### 5.4 Coasting (the continuity guarantee)
Every LLM level emits a **plan with an explicit expiry horizon**. C++ drains the plan's PlanOps deterministically on tick boundaries and **ramps effects over many ticks** (migration herd targets over ~60 ticks, faction objectives immediate, spawn quotas trickled) so nothing pops. On expiry with no replacement, ops fall to **steady-state continuation** (hold postures + natural ecology). Plan swap is atomic at a tick boundary (double-buffered pointer). Render lerps by alpha between ticks so motion is smooth regardless of agent latency.

### 5.5 Non-blocking (structural)
Provider runs HTTP/SSE on the I/O thread; intents land in a **lock-free queue drained at a tick boundary**. Deadline = 0.6× period. A late/failed/timed-out call returns the sentinel **"coast"** — a normal value meaning "reuse last plan," never an error, never a THROW. The sim thread never waits on a network call. Use streaming (`.get_final_message()`) for all large-output calls to avoid HTTP timeouts.

### 5.6 Cost levers
- **Prompt-prefix caching** (charter+tools+memory scaffold): cache-read at **0.1× input** (~90% saving), write 1.25× at 5-min TTL. Break-even at 2 wakes — trivially met by a persistent agent.
- **Decision cache** keyed on deterministic situation-hash: identical inputs replay the cached intent at **zero tokens** (routine is free).
- **Batch API (50% off)** for latency-insensitive reflection/summary calls.
- **Task Budgets (beta, `task-budgets-2026-03-13`, min 20k tokens, Fable5/Sonnet5/Opus4.8/4.7):** surface a countdown so the model self-moderates a strategic wake. *Note: subscription-first only — not on Bedrock/Vertex/Foundry.*

### 5.7 Routing and degradation
`route(snapshot, budget, provider_state, seed)` — a pure, replayable function. **Cloud-first; the cheap tier is a cheaper cloud model + caching/batching, not a resident local model** (rz 2026-07-05: don't spend unified memory/GPU on an on-device LLM — the renderer needs them more):
- ZONE → Opus 4.8 (or Sonnet 5 in economy mode)
- FACTION/REGION → Sonnet 5 when score>0.5, else Haiku 4.5
- ECOLOGY + most NAMED wakes → Haiku 4.5, aggressively prompt-cached + Batch-API'd (50% off, latency-insensitive)
- **On-device SLM: optional, small, off by default.** A tiny quantized model may back trivial flavor text on a hard-offline device, but it is never load-bearing and never sized to compete with the renderer for unified memory. If it's not there, the feature just isn't there offline.

**Fixed skip order on budget/RPM/offline exhaustion:** (1) skip L2 model calls → units coast on reflex; (2) skip cold L1s → those factions coast on last regional plan; (3) **never skip *applying* an already-committed L0 plan, only skip *recomputing* it.** Degrades LLM-alive → coasting → **strategic evolution frozen (thin)** — the near-player C++ executor keeps running so the game stays playable; the living world simply pauses until budget/connection returns. No rich offline shadow sim.

## 6. Proper wildlife: ecology agent + light guardrail scaffold

This **replaces §3 of the prior spec** (deterministic Lotka-Volterra + LLM-as-advisor). The pivot inverts it: the LLM authors, C++ does the arithmetic.

### 6.1 The critique resolved: is pure-LLM ecology stable? No. Hybrid-required.
An LLM is a *mediocre quantitative ecologist* — it hallucinates magnitudes, forgets it wiped a species, and oscillates (grow/collapse/grow). The honest verdict is **hybrid-required, not LLM-alone.** The LLM is the ecologist's *intent*; C++ is the ecologist's *arithmetic*.

### 6.2 The ecology agent (coarse authorer)
One ECOLOGY agent in V1 (per-biome subagents in V3), waking ~30 in-game min. Reads an `EcologyDigest` (bucketed counts, 3-tick trend arrows, hunger band, prey/predator ratio band, carcass load, anomaly/rad/day-phase, notable events, **guardrail reason codes from last tick**). Returns an `EcologyIntentBatch` of **bounded-rate bands, never raw counts:** `SET_BREEDING_RATE(region,species,band∈{collapse,decline,steady,grow,boom})`, `SET_PREDATION_PRESSURE`, `SET_MIGRATION`, `NOTABLE_INDIVIDUAL`, emission-aftermath hints. Bands, not equations, not absolute numbers — this is what makes it cheap, replayable, and clampable.

### 6.3 The light guardrail scaffold (C++, NOT an ecology sim)
Validate/clamp at ingest AND apply-tick:
1. **Carrying-capacity clamp** per (region,species) from area/flora/shelter — a BOOM saturates instead of exploding.
2. **No-instant-extinction / no-instant-explosion:** per-tick |delta| capped to ±CAP_FRAC.
3. **Integral bound** on cumulative agent-authored magnitude per region per game-day (a stuck agent can't ratchet).
4. **Conservation asserted at every band transition** (logged, never THROW).
5. **True local extinction allowed** (no floor) but **re-colonization is migration-only** — the guardrail refuses a SEED into an isolated extinct region.

### 6.4 Retain the band-transition damping layer (resolving critique P1(c), keep-scaffold #2)
The critique flags LLM oscillation as a *visible* tell near the player (overrun Tuesday, dead Wednesday). Add a **thin deterministic hysteresis/damping layer** over authored bands so a "collapse" after a "boom" is rate-limited. `wildlife-under-agents` worried this "re-introduces the smoothing the pivot rejected" — **it should, and we accept it.** It is cheap, deterministic, testable, and the only thing between us and a visibly bipolar ecology. This is *smoothing*, not *simulation* — the LLM still authors direction.

### 6.5 Materialized believability
Authored bands become **behavior-tree biases**: a "boom/low-hunger" dog cohort materializes as a large confident territorial pack (via existing `ai_monster_squad_manager`, `CMonsterHome` radii, existing reflex states eat/rest/panic/attack/home_point/find_enemy/steal); a "starving/declining" cohort materializes as gaunt, desperate animals that hunt aggressively and flee less. Believability flows *from* the coarse narrative state. A shared `daytime[0..1]` scalar (read by fauna, squads, anomalies alike) clusters hunts at dusk/dawn via BT modulation, independent of the agent.

## 7. Persistence, record/replay determinism, testability

### 7.1 What "determinism" now means
The recoverable substrate is four things: (a) the coarse store, (b) each agent's memory, (c) each agent's in-flight plan, (d) the append-only **tool-call ledger**. The ledger is the single source of determinism: **replay = serve the recorded response instead of calling the model, and the same deterministic C++ path reproduces the world bit-for-bit.**

### 7.2 The AgentToolBus (recordable choke point)
Every agent tool-call passes through one C++ dispatcher that stamps `{seq, agent_id, sim_tick, wall_ns, tool, request_json, response_json, provider, model, tier, latency_ms, tokens_in/out, cost_micros, validator_verdict, critic_verdict}` and appends to the session ledger **before** the mutation touches the store. In replay mode it serves the recorded response keyed by `(agent_id, sim_tick, tool, request_hash)`.

### 7.3 Snapshot = store + agent memory + in-flight plans + PRNG + ledger tail
Versioned IWriter/IReader; copy-on-write off the sim thread; one codepath serves save-game, agent-context projection (lossy per-region), and bridge replay (bit-exact).

### 7.4 The critic / nonsense-guard
After validation, a bounded sanity pass over the *proposed* delta before apply: conservation, magnitude-vs-history (>N sigma → quarantine), contradiction-with-active-plan, dead-world/runaway. Pure C++ on metrics; an optional on-device SLM critic on the digest is **advisory-only and always recorded** (keeps the accept/reject decision deterministic — an LLM never *judges* its own Zone in a way that feeds the determinism-critical path).

### 7.5 The replay gate is a CI blocker from day one (resolving critique P1 non-determinism)
The critique is right that this gate is load-bearing and silently fragile. Make it a **CI blocker, not an acceptance-time check.** Requirements:
- **Fixed-point firewall total** — one float in a persisted cohort field breaks byte-identity. Every store-writing reduction id-ordered (materialize is already excluded from the parallel-jobs phase — good).
- **SSE partial-completion:** the shim records the *final assembled response only* and records the coast-vs-apply decision as a value.
- **Cross-agent drain order** is `seq`-authoritative and tested *adversarially*: inject latency skew in replay and assert identical merge.
- **Record reads, not just writes** — a read returning wall-clock or budget state that isn't recorded diverges replay. Accept the ledger-size cost.
- **Determinism fuzzer** on the bridge: same seed, injected latency/retry/partial-stream perturbations, assert byte-identical snapshots.

### 7.6 Testability + new bridge verbs
Headless fast-forward soak (`zonesoak.py`) in LIVE / REPLAY / DETERMINISTIC-NULL modes; fixed-schema per-tick MetricRecord; declarative temporal assertions evaluated in **pure C++/Python (never LLM-judged)**; always-on watchdogs (dead-world, runaway, oscillation, incoherence). New `agent.*` / `ai.*` verbs extending the existing socket:

`agent.list`, `agent.wake <id>`, `agent.memory <id> [get|set-summary|dump-episodic|prune]`, `agent.record on/off <path>`, `agent.replay <path> [--to-tick N]`, `agent.budget [<id>|session]`, `agent.inject <intent-json>`, `agent.tree <tick>`, `agent.provider on/off/local`, `agent.tree`; plus retained `sim ff|step|pause`, `snap|restore`, `assert load|eval`, `metrics dump`, `seed`, `eco dump_cohorts|inject_intent`.

**Acceptance gate:** record a LIVE session, replay it, assert byte-identical store snapshots at every checkpoint tick AND identical reconstructed agent-tree shape.

### 7.7 Conservation watchdog with teeth (resolving critique P2 silent drift)
Since we can't THROW on Darwin, "watch-dogged" needs a hard stop: on any `sum(live+dormant+statistical) != expected mod logged births/deaths`, the watchdog **quarantines the region and reloads it from the last good snapshot** rather than letting drift compound over 100 hours.

## 8. The honest tradeoffs vs. the prior deterministic design — and retained scaffold

| Dimension | Prior deterministic sim | Agentic Zone | Verdict |
|---|---|---|---|
| **Cost** | ~$0 | $3-8/wall-hr lively, ~$0 idle | Real, ongoing, per-player |
| **Latency** | frame-rate | strategic decisions minutes apart; game coasts | Acceptable *only because* near-player is C++ BTs |
| **Online** | fully offline | effectively online for headline feature | Honest product constraint |
| **Determinism** | seed-reproducible | only reproducible via recorded tool-calls | The biggest regression |
| **Believability** | mathematically balanced, narratively flat | narratively rich, needs guardrails to stay sane | The whole reason to pivot |

**The four places a thin deterministic scaffold is retained (explicit answer to the critique):**
1. **Near-player tactical loop** — squad/pack target selection, flee/flank, day/night — permanently C++ BT, LLM never on the frame-critical path. (§4.1)
2. **Band-transition damping/hysteresis** — smoothing over agent-authored ecology bands so the world can't visibly flip-flop. (§6.4)
3. **Offline is a THIN coast, not a scaffold to invest in** (rz 2026-07-05, revising the earlier "first-class shadow" call). When the provider is unreachable, the near-player C++ executor keeps running (move/fight/loot/survive) while the Zone's strategic evolution **freezes and coasts on its last plan** until reconnect. We deliberately do **not** build a rich offline second-game and do **not** host a resident on-device LLM — **local unified memory and GPU belong to the renderer and physics.** The offline floor is "playable but the living world is paused," and that is the intended, honest experience. (below)
4. **Conservation + carrying-capacity + rate-limit guardrails** — the "arithmetic" C++ does while the LLM does "intent." Keep exactly as designed; it's the model. (§3.3, §6.3)

**On the offline floor (resolving critique P1 online-outage):** the true offline floor is a **thin freeze-and-coast**, not a local LLM world. This closes the earlier open question about shipping a 7-8B on-device model: **we don't** — a resident model that size would claim gigabytes of unified memory and GPU cycles the Metal renderer (RT, fidelity) uses far better. Any on-device SLM is optional, tiny, off by default, and never load-bearing. The living Zone is an online feature; offline you still have a fully playable STALKER, just with a world that holds its breath.

# Appendix — detailed design fragments

## The Agentic Runtime Harness — the persistent, tool-using agent substrate that IS the Zone's world simulation (Claude Code / Codex agent pattern applied to a game world; harness owned by us, running against Claude/OpenAI models with on-device SLM fallback)

We own the harness; we do NOT embed Claude Code / Managed Agents as products. The harness is a C++ `xrAgentRuntime` subsystem (peer to xrSim, reachable over the agent bridge) that instantiates our own `WorldAgent` objects and drives their reason-act loop against a provider abstraction (`IAgentProvider`: cloud Claude/OpenAI, or on-device llama.cpp-Metal SLM). The core object is a long-lived `WorldAgent`: a stable `agent_id` (never regenerated — mirrors xrSim's entity-id invariant), a `scope` (ZONE | FACTION | REGION | ECOLOGY | NAMED_INDIVIDUAL), a versioned `charter` (immutable system-prompt/identity — think of it as the agent's persisted config, versioned like a Managed-Agents agent object so a run pins to a charter version for replay), a `memory_ref` into a per-agent persistent memory store, a `tool_set` (schema-constrained world-mutation + query tools), a `budget` (tokens+latency+dollars per wake), and `continuity_state` (last plan, last situation-hash, pending subagent handles, reflection cursor). The crucial difference from a one-shot API call — and the whole reason to build a harness — is CONTINUITY: a WorldAgent persists across many wakes over a whole playthrough, carries forward summarized memory, re-reads and revises its own prior plan rather than re-deriving the world from scratch, and is the same object across save/load (its memory + charter-version + last plan serialize into the xrSim snapshot). The reasoning loop is the classic agent loop scoped to a world slice: on wake, xrSim renders a compact scoped `observation` (the Part-II context-slice renderer), the harness assembles the prompt as [charter (cached prefix) + tools (cached) + rolling memory summary (cached per-agent) + volatile observation], the model thinks and emits tool calls, the harness validates each tool call two-phase (schema, then sim-legality at apply-tick) and applies it as an intent to xrSim, results feed back, and the loop repeats until the agent emits a `commit_plan` tool call or exhausts budget — then it sleeps until its next trigger. Cadence is surprise-driven not clock-driven (the sim wakes the agent on a novelty/stakes threshold; the clock only permits, never forces, a wake), so a stable Zone hour costs near-zero tokens. Hierarchy is orchestrator-worker: the ZONE agent is the persistent orchestrator; it spawns scope-minimized FACTION/REGION/ECOLOGY subagents by handing each a self-contained task packet (objective / scoped observation / output schema / boundaries — the four-field discipline from Anthropic's multi-agent research system) with FRESH context so children never see siblings or the orchestrator's full reasoning; children return schema-only intents; the parent does a deterministic merge (no re-reasoning) and hands the batch to xrSim. Subagents are mostly ephemeral (spawned per wake, cheap, discarded) EXCEPT NAMED_INDIVIDUAL agents which are long-lived like the orchestrator (a memorable named stalker keeps his own memory across the campaign). Memory architecture is three-tier per agent: (1) charter (frozen identity), (2) a bounded rolling REFLECTION summary (after each wake the agent — or a cheap Haiku summarizer subagent — compresses "what changed and why" into <~1-2k tokens, so context never grows unbounded across a 40-hour playthrough), and (3) an episodic log of committed intents (the replay/audit backbone, stored in the sim, not resent to the model). We keep the FrugalGPT collapse discipline: the harness runs each level's deterministic shadow first and only escalates a genuine WorldAgent wake on surprise, so "alive" agents are few. Aliveness is hard-bounded: exactly 1 persistent ZONE orchestrator always resident; ≤8 FACTION/REGION subagents per strategic tick (fan-out cap); a small roster of long-lived NAMED_INDIVIDUAL agents capped (e.g. ≤16) with LRU demotion to a dormant record when off-screen and quiet; ECOLOGY agents pooled per-active-region. Everything is recordable: every {packet→response} goes through the recordable provider shim so a live run can be replayed deterministically (recorded responses served instead of live calls) — this is how a probabilistic long-lived agent tree becomes a deterministic input for tests and save-load. Provider routing is subscription-first: ZONE→frontier (Opus 4.8), FACTION/REGION→mid (Sonnet 5 / Haiku 4.5), ECOLOGY + most NAMED wakes→on-device SLM; on cloud-unavailable the whole tree degrades to on-device then to xrSim's deterministic shadows, and the game never blocks (it coasts on the last committed plan).

- **WorldAgent object + charter versioning** [n/a (harness object) / created at world-init or at reference-time (a named NPC promoted to an agent); destroyed only on true retirement]: Persistent C++ object: {agent_id (stable, never regenerated), scope, charter_version, memory_ref, tool_set, budget, continuity_state{last_plan, last_situation_hash, subagent_handles, reflection_cursor}}. Charter is an immutable versioned system-prompt/identity blob (persisted like a Managed-Agents agent config); a wake pins to a charter_version so replays reconstruct the exact prompt. Serialized into the xrSim snapshot so the agent is the SAME object across save/load — the defining property vs a one-shot call.
- **Reason-act wake loop** [tier by scope (see routing) / surprise-driven: sim wakes the agent on a novelty/stakes threshold; clock permits but never forces; agents coast on last plan between wakes]: observe (xrSim renders scoped observation) -> assemble prompt [charter+tools+memory-summary as cached prefix, observation as volatile suffix] -> model thinks -> emits tool calls -> harness two-phase-validates (schema, then sim-legality at apply-tick; illegal -> no-op + log, never a THROW) -> apply as xrSim intent -> feed results back -> repeat until commit_plan tool call or budget exhausted -> sleep. Prompt-prefix caching keeps charter+tools+memory near-free on repeat wakes.
- **Orchestrator-worker delegation** [ZONE=frontier orchestrator; children=mid/SLM workers / per strategic wake; fan-out hard-capped at 8 concurrent subagents]: ZONE orchestrator spawns FACTION/REGION/ECOLOGY subagents via spawn_subagent(objective, scoped_observation, output_schema, boundaries) with FRESH context (children see only their slice, never siblings/parent reasoning). Children return schema-only intents; parent does a DETERMINISTIC merge (fixed precedence, conflict tiebreak by agent_id) — no re-reasoning, so parent context never re-inflates. Subagents run in parallel (independent provider calls); parent awaits the batch but the game never blocks on it.
- **Three-tier per-agent memory + reflection** [summarizer: Haiku 4.5 (cheap) or on-device SLM / reflection runs at end of each wake or every N wakes when the summary drifts]: (1) charter = frozen identity. (2) rolling reflection summary: after each wake, compress 'what changed and why' into a bounded <~1-2k-token summary (self-written, or delegated to a Haiku summarizer subagent) so context stays bounded across a 40h playthrough. (3) episodic intent log stored in the sim (replay/audit backbone), never resent to the model. Memory store is per-agent and persisted in the snapshot.
- **Aliveness bounding + LRU dormancy** [n/a (admission controller) / 1 Hz occupancy/priority pass, same cadence as xrSim band recompute]: Exactly 1 resident ZONE orchestrator; ≤8 FACTION/REGION subagents per tick; ≤16 long-lived NAMED_INDIVIDUAL agents with LRU demotion to a dormant serialized record when off-screen and quiet (re-materialized with memory intact at reference-time); ECOLOGY agents pooled per active region. Ephemeral subagents are discarded after their wake. This is what keeps a live LLM world affordable.
- **Recordable provider shim + deterministic shadow** [Opus 4.8 (ZONE) / Sonnet 5 (hot FACTION) / Haiku 4.5 (cool FACTION, summarizer) / on-device SLM (ECOLOGY, most NAMED, all fallback) / record toggled via agent bridge; replay for CI/tests and deterministic load; shadow fires on any provider miss]: IAgentProvider wraps cloud (Claude Opus 4.8 / Sonnet 5 / Haiku 4.5) and on-device SLM behind a record/replay seam: every {packet->response} logged keyed by {agent_id,tick,charter_version,packet_hash}. In replay mode recorded responses are served instead of live calls, turning the probabilistic agent tree into deterministic input for tests and byte-identical save-load. Each agent level has a deterministic C++ shadow (behavior-tree/rule interpreter) invoked on timeout/over-budget/provider-down — a timeout is a normal expected value, never an error.
- **Budget-aware graceful degradation** [routing is pure fn of (scope-score, budget-remaining, provider-availability) — deterministic and replayable / checked continuously during a strategic tick]: Per-wake budget {input+output tokens, latency ceiling, $ cap} tracked as the harness dispatches; Task Budgets (beta) surface a countdown to the model so it self-moderates. Fixed skip order when exhausted: skip on-device NAMED wakes -> skip cool FACTION subagents (coast on last regional plan) -> never skip APPLYING the last committed ZONE plan, only skip recomputing it. Degrades LLM-alive -> coasting -> pure deterministic sim, never stalled.

*Tradeoffs:* Persistent agents cost more state than one-shot calls: per-agent memory + charter versions + continuity must serialize into every snapshot, inflating save size and snapshot time — mitigated by bounding live-agent count and storing episodic logs by reference.; Continuity can drift: a long-lived agent accumulating reflections may develop stale or self-reinforcing beliefs about the Zone; the bounded reflection summary is lossy and can compress away something that later matters.; Determinism is weaker than the pure-C++ sim and is only recovered via recording — a live (unrecorded) session is NOT reproducible, so bug repro and save-load fidelity depend entirely on the record/replay seam being airtight (charter_version + packet_hash must be exact).; Orchestrator-worker parallelism helps latency but the parent still awaits the subagent batch; a slow provider stalls a whole strategic tick's recompute (the game coasts, but the Zone stops evolving until the batch lands or times out).; The harness is real engineering surface we own and maintain: provider adapters, prompt-cache management, budget ledger, record/replay, subagent lifecycle — meaningfully more than calling an SDK, and it must stay robust under XRAY_EXCEPTIONS=0 (every failure path a value, never a throw).; On-device SLM quality is the fallback floor for believability: if a 1–4B model can't sustain a coherent NAMED_INDIVIDUAL persona across wakes, offline/degraded play feels noticeably worse than online, undermining the 'always alive' promise.; Aliveness caps are blunt: LRU demotion of NAMED agents can retire an individual the player was tracking; re-materialization restores memory but a wake gap can produce a visible discontinuity in that character's behavior.

## The World-State Store + Tool API — the C++/agent contract (thin authoritative coarse store; agents read/mutate it only through schema-constrained, validated, rate-limited, replay-stamped tools)

The store (`xrWorldState`) is a small, flat, LLM-legible authoritative record: ~30-60 Regions, 8-12 Factions, per-(region,species) population COUNTS, per-faction territory ownership + relation matrix, economy indices per region, active Events (emissions/anomaly blooms/wars), player reputation, and an entity roster of only NAMED/notable individuals (not per-NPC). It is a struct-of-arrays with stable u32 handles (24-bit index + 8-bit generation) that are NEVER regenerated, and all persisted numerics are fixed-point (floats live only in the near-player C++ executor and are re-derived on load). This store is the SINGLE source of truth shared by (a) LLM agents that evolve the off-screen world on slow narrative ticks and (b) the C++ near-player executor that materializes/coasts on it every frame. Agents never touch memory: they emit tool calls (structured-output JSON), and C++ is the sole mutator via a `ToolDispatcher`. Every write tool passes a THREE-STAGE gate: (1) ingest validation against the snapshot the agent's context was built from — schema/type, handle existence, enum legality, range clamp; (2) conservation + rate/quota checks — population deltas bounded per region per game-day (integral, not just per-call), a force move cannot cross non-adjacent regions or exceed a hops-per-day budget, ≤1 emission per region per N ticks, reputation deltas clamped; (3) apply-tick re-validation at drain time because the async agent call spanned many ticks and handles may have died — a dangling ref DEGRADES to the region aggregate or is dropped-with-feedback, and CRITICALLY never reaches a THROW (fatal on XRAY_EXCEPTIONS=0 Darwin). Rejections are returned to the agent as tool-result values (`{ok:false, reason, suggestion}`) so a bad call is a no-op with feedback the model learns from, never a crash. Every accepted mutation is stamped into an append-only `ToolLog` (agent_id, tool, args, seed, ingest_tick, apply_tick, content_hash) so a session replays bit-identically by re-feeding the log with the LLM turned OFF — this is how weak determinism is recovered and how the agent bridge tests the whole thing headlessly. Rate-limits are the load-bearing anti-cheat: they stop an agent from teleporting a faction across the map, wiping a species in one call, or thrashing relations — legality lives in C++, direction lives in the LLM, RATE lives in C++. Read tools return the same bucketed, token-budgeted projections the agent's context is built from, so read-then-write operates on a consistent view. The tool surface is deliberately ~20 tools: enough to author factions/ecology/economy/quests/events, small enough to fit an agent's schema and be exhaustively validated. Reads are cheap and idempotent; writes are scarce, clamped, logged, and reversible via snapshot.

- **xrWorldState store** [C++ (no model) / Read every frame by executor; mutated only on validated tool apply]: Flat SoA authoritative coarse store: Region[], Faction[] (ledger + relation_matrix + owned_regions), PopCohort[region][species] as fixed-point COUNTS, EconIndex[region][commodity], Event[] (active emissions/wars/blooms with eta/ttl), PlayerReputation[faction], Individual[] roster of NAMED entities only. Stable u32 handles (index+generation, never regenerated). Fixed-point for everything persisted. Single source of truth for both agents and the near-player C++ executor.
- **ToolDispatcher (3-stage gate)** [C++ (no model) / Ingest at agent-call return; apply at next sim tick boundary (queue drained on sim thread)]: Sole mutation path. Stage 1 ingest-validate vs the snapshot the agent context was built from (schema/type/handle-exists/enum/range-clamp). Stage 2 conservation + rate/quota (integral per-region-per-day population bounds, hops/day force-move budget, ≤1 emission/region/N ticks, relation-delta clamp, last-writer-wins on intra-batch conflict). Stage 3 apply-tick re-validate vs CURRENT state (async gap) — dangling ref degrades to region aggregate or drop-with-feedback, NEVER a THROW. Rejections returned as {ok:false,reason,suggestion} values.
- **ToolLog (replay stamp)** [C++ (no model) / On every accepted tool apply; reflection/prune not needed (bounded by session)]: Append-only ledger of every ACCEPTED mutation: {agent_id, tool, args, seed, ingest_tick, apply_tick, content_hash, model+tier}. Serialized inside the snapshot. Replaying the log with the LLM disabled reproduces a session bit-for-bit; also the CI + agent-bridge test fixture. Rejected calls logged separately for eval, not replayed.
- **Read tools (observe)** [C++ serving; consumed by any agent model / On agent demand during its reasoning loop]: observe_region(region)->counts/control/hazards/econ/events; query_faction(faction)->ledger/relations/goals/territory; list_events(scope)->active events; get_roster(region|faction)->named individuals; get_relations()->matrix; observe_economy(region)->price indices; read_reputation(faction). All idempotent, return the SAME bucketed token-budgeted projection the context is built from so read-then-write is consistent. No side effects, not logged.
- **Write tools — faction/territory** [Faction agents on Opus/Sonnet / Slow strategic agent ticks]: move_force(faction,from_region,to_region,size,intensity) [adjacency + hops/day budget]; set_relation(faction_a,faction_b,delta∈-1|0|+1) [clamped, folded by one deterministic update fn: decay→player-spillover→agent-nudge]; set_control(faction,region,share_delta) [conservation: shares sum≤1]; declare_event(war|truce, faction_a, faction_b).
- **Write tools — ecology** [Ecology agent on Sonnet/Haiku (coarse) / Ecology agent on eco ticks]: adjust_population(region,species,delta) [integral per-region-per-day bound, carrying-cap clamp, true local extinction allowed — no floor]; set_migration(species,from_region,to_region,pressure); seed_population(region,species,count≤cap); set_breeding(region,species,factor∈[0.5,2]).
- **Write tools — economy** [Economy agent on Haiku / Economy agent tick]: set_price(region,commodity,index_delta) [clamped band]; set_supply(region,commodity,delta); set_trade_route(region_a,region_b,open|closed|cost). Economy indices are coarse multipliers the near-player trader executor reads.
- **Write tools — events/narrative** [Director agent on Opus / Zone-director / narrative agent tick]: spawn_event(type∈emission|psi_storm|anomaly_bloom|raid, region, severity, eta_ticks) [quota ≤1/region/N ticks]; author_quest(giver_ref, region, archetype, target_ref, reward_band) [giver-liveness precondition, expiry]; set_narrative_beat(scope, text_key, trigger); adjust_reputation(faction, delta) [clamped, routed through relation update fn].
- **Write tools — individuals** [Director / faction agents / When an agent needs a named actor for a quest/story]: promote_individual(region,species|type,name,role) — turns an anonymous count-member into a persistent NAMED roster entry with a permanent handle (the count is decremented; conservation); demote/retire_individual(handle) — returns to aggregate or marks dormant. This is the coarse<->named boundary agents use to give the world characters without per-NPC simulation.
- **Snapshot/restore** [C++ (no model) / On save, on agent-context build, on replay load]: Snapshot = {version, content_hash, tick_count, PRNG states, store SoA blobs, named roster, agent memory blobs, ToolLog tail}. Near-memcpy on UMA, copy-on-write off the sim thread. Serves save-game, agent-context projection (lossy per-region), and bridge replay (bit-exact) from ONE codepath.

*Tradeoffs:* Weaker determinism than a pure C++ sim: bit-exact reproduction depends on the ToolLog + pinned model/tier/seed; a live (non-replay) session with a frontier model is inherently non-reproducible. Mitigated by recording tool-calls, not the sim, and replaying with the LLM off — but a live bug may not recur without the exact log.; Rate-limits create a believability gap: because an agent physically cannot teleport a faction or wipe a species instantly, some dramatic narrative beats the LLM 'wants' unfold slower than it intends. The C++ executor must coast convincingly across many agent-silent ticks or the world feels laggy/stale.; The coarse store is lossy by design: it holds COUNTS and named individuals, so any agent desire that needs per-NPC granularity (a specific unnamed stalker's fate) can't be expressed except by promote_individual, which pressures the roster to grow and re-introduces cost the coarseness was meant to avoid.; 3-stage validation duplicates checks (ingest vs apply-tick) and adds latency + code surface; the apply-tick re-validation is stability-critical on Darwin (a missed dangling-ref path = fatal abort), so this is high-risk code that must be exhaustively tested via the bridge.; Effectively-online: without a capable on-device SLM fallback, the world stops evolving when the provider is unreachable or the token cap is hit — the game stays playable (executor coasts) but the Zone goes narratively inert. The DETERMINISTIC-NULL fallback is a floor, not a substitute.; Conservation invariants across the coarse<->named boundary (promote/retire decrementing counts) are easy to get subtly wrong; a leak double-counts or vanishes population, and on XRAY_EXCEPTIONS=0 the assert is a logged value, not a throw, so silent drift is possible if not watch-dogged.; Agent adversarial/degenerate behavior: a confused model can spam rejected calls (wasted tokens) or find a legal-but-pathological sequence (e.g. oscillating relations at the clamp edge). Rate-limits bound damage but not token waste; needs eval on the rejected-call log.

## The Materialization Boundary — coarse agent-owned region state ⇄ concrete real-time C++ entities (materialize / dematerialize+reconcile / live intent redirect)

The boundary sits between two authorities that must never both own the same entity at the same time: the LLM-agent-owned COARSE store (per-region PopCohort counts + a small set of persistent "notable" records with permanent u32 ids) and the C++ real-time layer (live SoA entities with physics/animation/reflex behavior trees). I keep the existing engine seam — `CALifeSwitchManager::switch_online/offline` is fundamentally an attach/detach of a physics+render+AI proxy and is NOT a spawn — but reframe it: STATISTICAL→OFFLINE materialize() and OFFLINE→STATISTICAL dematerialize() are the count⇄entity conversions, while ONLINE⇄OFFLINE stays the cheap proxy attach we already have. materialize() runs as a SINGLE-THREADED, region-id-ordered, budget-bounded, TRICKLED pass off the `materialize` PRNG stream seeded from (region_id, sim_day): it reads Region.population[species/faction] and the region's notable-record list, decrements the cohort as it draws (conservation), places entities on graph vertices weighted by smart-terrain capacity, assembles packs/squads per authored size distributions, seeds each entity's LOCAL utility-scored behavior tree from its need vector, and re-attaches every notable record BY ID (never a fresh id) so a named survivor is literally the same entity that dematerialized. Anonymous fauna get EPHEMERAL ids scoped to this materialized lifetime ("a different rat next time," honestly); anything a quest/agent-intent/save references is a persistent DORMANT record and re-attaches unchanged. dematerialize()/reconcile() folds live entities back: `cohort.count += survivors`, records births/deaths/kills that happened, and PROMOTES anything the player touched — a squad the player half-wiped writes back its reduced count + the specific corpses/loot as a per-region scar entry; an artifact the player took is removed from the region's resource ledger; named/protected/quest-giver/squad-leader entities never dissolve into a count, they demote to a DORMANT record with id retained. The player's actions persist because reconcile is the ONLY writer back to the coarse store on this path and it diffs live-state against the cohort it drew from. Consistency rests on four invariants asserted (logged, never THROW, because XRAY_EXCEPTIONS=0 is fatal on Darwin) at every transition: (1) single-authority — count is truth XOR entities are truth, gated by band; (2) conservation — sum(live+dormant+statistical) per faction/species is conserved modulo explicitly-logged births/deaths; (3) stable ids — a notable id is never regenerated across any number of materialize/dematerialize cycles; (4) no-dangling-ref — validated at both ingest and apply-tick. Near-player entities run REAL-TIME C++ behavior trees (the reflex/L3 tier), never the LLM — a materialized blind-dog pack hunts, flees, and dies by deterministic utility trees at 30 Hz, not by a model call. Agent decisions reach materialized entities through INTENT REDIRECTION, not respawn: when the async agent authors an intent (e.g. faction_posture bandits→cordon:advance, or migration blind_dogs garbage→agroprom) it compiles to a PlanOp that writes a REGION-LEVEL objective/herd-target field; the live squad's/pack's behavior tree reads that field as its current goal and re-steers next tick — the executor redirects the live unit, it does not tear it down and rebuild it. The whole boundary is testable over the agent bridge: `sim ff` to force a region hot, `snap`/`restore` around a materialize/dematerialize cycle, and a conservation-assert metric that must hold bit-exact in REPLAY.

*Tradeoffs:* Anonymous-entity id instability is an accepted lie: the third rat you meet in a region is genuinely a different rat with a different ephemeral id. Nuance (which bandit, exact positions, who fled where) is discarded unless captured as an explicit scar/notable, so 'this happened while I was away' fidelity is bounded by how much we choose to promote — over-promote and the store bloats, under-promote and the world feels amnesiac.; Determinism is weaker than a pure C++ sim: materialize draws are deterministic given the seed, but the COARSE state feeding them was authored by an LLM at coarse granularity, so exact concrete outcomes are only reproducible via recorded intents in REPLAY mode, not derivable from first principles.; Trickled materialization trades believability for frame safety: forcing entities to appear over N ticks means a player who sprints into a freshly-hot region can briefly out-run the population and see it fill in behind them — acceptable but visible under adversarial movement.; Intent-redirect latency: because agents fire on a ~90 s trigger and the world coasts on the last plan between, a live squad may pursue a now-stale objective for up to a plan horizon before the agent re-steers it — the world is reactive on the order of minutes, not seconds, near the seam.; The single global 150–200 ONLINE budget means a faction war + a dog overpopulation + an emission all landing in one region degrades some entities to OFFLINE math mid-combat; graceful, but a sharp-eyed player near the cap can notice distant fighters 'thinking slower.'

## Cadence, Cost, Coasting & Non-Blocking — the economics and continuity layer that makes an all-agent Zone shippable

This dimension owns the answer to "how does a world simulated by LLMs run continuously, affordably, and never stall?" It sits astride the tick loop (§6.1, 100 ms integer tick), the async provider (§5.6), and the L0-L4 compute tree (Part II), and it makes three guarantees: the game never blocks on an agent, the world is visually/behaviorally continuous between slow agent decisions, and per-session cost stays inside a subscription-mappable envelope with graceful degradation to a fully-playable zero-LLM sim. The spine is a per-tick and per-session TOKEN/COST LEDGER (extending Part II §4) that every dispatch decrements and that drives a FIXED SKIP ORDER when exhausted. CADENCE: L0 Zone Director fires on a wall-clock TRIGGER of ~90 s (config `zone_director_period_s`, roadmap says 60-180 s / 2-6 in-game hours), rate-limited to min 30 s between calls and max 1 in flight; L1 faction/region subdirectors fire ~15-40 s wall for the 3-8 HOT factions/regions only (quiet factions get zero calls); L2 squad/pack micro-decisions are ~90% collapsed to deterministic C++ and only escalate on a deterministic SURPRISE flag. The clock only PERMITS a call; SURPRISE (broken precondition, stakes threshold, player action outside the last plan, low-confidence child) is what actually WAKES an agent — a perfectly stable in-game hour costs near-zero tokens. COASTING is the continuity mechanism: every LLM level emits a PLAN with an explicit expiry horizon (L0 plan_horizon_ticks ~120, i.e. 4 in-game hours), C++ drains the plan's PlanOps deterministically on tick boundaries and ramps effects (migration herd targets, faction objectives, spawn quotas) over many ticks so nothing pops; on plan expiry with no new plan, ops fall back to STEADY-STATE CONTINUATION (hold postures, natural ecology dynamics) so the Zone never freezes. NON-BLOCKING is structural: the provider runs HTTP/SSE on the I/O thread, intents land in a lock-free queue drained at a tick boundary (agent-bridge §threading, L4 marshalling); deadline = 0.6x period; a late/failed/timed-out call is a NORMAL VALUE that means "coast on last plan," never an error, never a THROW (critical on XRAY_EXCEPTIONS=0 Darwin). COST CONTROL layers four levers: batching (one L1 call plans ALL its squads; L2 groups same-kind surprised units into one array-output call — counters the ~15x multi-agent token blowup), a DECISION CACHE keyed on the deterministic situation-hash (same inputs -> replay cached intent, zero tokens), PROMPT-PREFIX CACHING of the stable schema/boundaries/digest scaffold (cache reads at 10% of input price — 90% saving), and the Batch API 50% discount for non-latency-sensitive reflection/summary calls. ROUTING is a pure replayable function route(snapshot, budget, provider_state, seed): L0 -> Opus 4.8 (or Sonnet in economy mode) always; L1 -> Sonnet/Haiku when score>0.5; L2 escalations and wildlife -> on-device SLM (llama.cpp-Metal 1-4B on unified memory) or Haiku batch. OFFLINE story: no connectivity -> L1/L2 fall to the on-device SLM at reduced schema, L0 falls to NOT-RECOMPUTING (coast on last Zone plan indefinitely); after K provider failures the Director is SUSPENDED (`! ZoneDirector suspended` logged) and the game runs on the pure deterministic A2 sim — frozen-but-alive, fully playable. Everything is RECORDED (packet+response keyed by agent_id+tick) so a LIVE run replays bit-exact, recovering the determinism a pure C++ sim would have had.

## Proper wildlife under an agent-authored world: a believable Zone ecology (predator/prey, packs, territory, migration, breeding, carrion, anomaly/radiation micro-habitats) where an LLM Ecology Agent AUTHORS population dynamics at coarse granularity, light C++ guardrails keep it physically sane WITHOUT running the ecology math, and real-time behavior trees materialize believable hunting/territorial/day-night behavior near the player. This REPLACES §3 of 2026-07-05-zone-simulation-design.md, which still used deterministic Lotka-Volterra + LLM-as-advisor; the pivot inverts authority.

The ecology is authored by LLM agents at region/species/cohort granularity, NOT by C++ equations; C++ owns only a thin authoritative PopCohort store, cheap deterministic COASTING between agent decisions, and a set of physical-sanity guardrails that clamp/veto agent intents but never themselves simulate predator-prey math. Data model per (region, species): PopCohort{count fixed-point, count_prev, biomass, hunger_avg, breeding_accum, rad_tolerance, den_region, migration_target} — carried over from the parent spec's SoA store, unchanged as the state contract, because C++ near-player mechanics, saves, and the agent all read/write this one representation. The single ECOLOGY AGENT (V1; per-biome subagents in V3) runs at the ECO cadence (default ~30 in-game min = 300 ticks wall-triggered, async, off the sim thread) and receives an EcologyDigest per region — bucketed counts, 3-tick trend arrows, hunger band, prey/predator ratio band, carcass load, anomaly/rad/emission state, day-phase, notable events (a wolf pack starved, an emission wiped Garbage), and director_feedback (guardrail reason codes from last tick). It returns an EcologyIntentBatch of BOUNDED-RATE intents (never raw counts): SET_BREEDING_RATE(region,species,band∈{collapse,decline,steady,grow,boom}), SET_PREDATION_PRESSURE(predator,prey,region,band), SET_MIGRATION(species,from,to,urgency), NOTABLE_INDIVIDUAL(spawn/name a specific animal — an alpha, a mutated giant — promoted to a persistent dormant record), and EMISSION/BLOOM ecological aftermath hints. Crucially the agent authors RATES and DIRECTIONS as small integer bands, not equations and not absolute numbers — this is what makes it cheap, replayable, and clampable. Between ECO ticks C++ COASTS: it applies the last authored bands as simple monotone deltas (count += rate_band * dt clamped by guardrails), moves migrating fractions along region-adjacency edges at plausible speeds, decays carcasses, and regenerates flora — deterministic, near-free, and it NEVER blocks waiting on the agent. Guardrails are the honest answer to "is an LLM a good ecologist?": no, not alone — it hallucinates magnitudes, forgets it wiped a species, and oscillates. So C++ enforces (1) carrying-capacity clamp per (region,species) from region area/flora/shelter so a BOOM band saturates instead of exploding; (2) no-instant-extinction and no-instant-explosion: per-ECO-tick |delta| capped to ±CAP_FRAC of count, so even a bad "collapse" band takes several ticks and stays recorded/reversible; (3) integral bound on cumulative agent-authored magnitude per region per game-day (the parent spec's C4 fix) so a stuck agent can't ratchet; (4) conservation-with-logged-births/deaths asserted at every band transition (never a THROW on Darwin — logged); (5) true local extinction IS allowed (no floor clamp) but re-colonization is migration-only, and the guardrail refuses a SEED into an isolated extinct region so the agent can't teleport life back. Near the player, STATISTICAL cohorts materialize into live behavior-tree entities (the parent spec's promotion path, unchanged): a materialized pack seeds a real-time BT from the coarse state — pack leader + members via existing ai_monster_squad_manager, territory via CMonsterHome (min/mid/max radius, aggressive flag), and existing reflex states (eat, rest, panic, attack, home_point, find_enemy, steal, squad_rest) selected by a small utility scorer over need×context. The agent's authored bands become BT BIASES: a "boom/low-hunger" dog cohort materializes as a large confident territorial pack that patrols and challenges; a "starving/declining" cohort materializes as gaunt, desperate animals that hunt aggressively at range and flee less — believability flows FROM the coarse narrative state, so what the player sees is consistent with what the agent decided off-screen. Day/night is a shared daytime[0..1] scalar (read by fauna AND squads AND anomalies) that clusters hunts at dusk/dawn via BT modulation, independent of the agent. Anomaly/radiation are habitat modifiers the guardrail applies to carrying capacity (rad-tolerant mutants get predator-free refuges; anomalies raise pathing cost and occasionally feed on panicked animals), and the agent reads their state but does not simulate them. Balance/stability without equations comes from the guardrail scaffold doing the CONSERVATION and BOUNDING while the agent does the NARRATIVE STEERING ("dogs are overrunning Garbage, push them toward Agroprom, let the flesh recover") — a hybrid where the LLM is the ecologist's INTENT and C++ is the ecologist's ARITHMETIC. Determinism is recovered by recording the agent's IntentBatch bytes + apply-tick + model/tier/seed (parent spec's replay contract) so a run replays bit-identically; provider-off mode coasts on the last bands forever, giving a fully playable token-free baseline and the A/B control that proves the agent ADDS liveliness (migration flux, boom/bust cycles, notable individuals) without breaking the guardrails the null run held.

Reads EcologyDigest, holds rolling memory of population history + past mistakes (grudges against its own bad seeds), emits bounded-band intents via structured output. Never addresses an individual animal except via NOTABLE_INDIVIDUAL; never sets a raw count; never runs per-frame or per-NPC-per-tick.
- **Deterministic ecology COAST (C++)** [No LLM — pure fixed-point deterministic C++ on the sim thread / Every ECO_TICK (300 ticks) for band application; carcass/flora decay folded into the same pass; catch-up integrator batches many ECO_TICKs deterministically on time-skip (sleep/fast-travel)]: Between agent ticks, apply last-authored rate bands as monotone integer deltas to PopCohort.count (delta = band_to_rate(band)*dt), diffuse migrating fractions along region adjacency at plausible speed, decay CarcassResource, regen flora nodes. Guardrail reason codes fed back as director_feedback so the agent learns its seeds keep getting density-killed.

Authored bands (hunger, confidence, breeding) become BT biases so on-screen behavior matches off-screen narrative state.
- **Record/replay + provider-off A/B** [Deterministic C++/Python assertions — an LLM never judges its own ecology (would poison the signal) / Metrics sampled every sim tick to ring buffer + NDJSON; watchdogs (unintended zone-wide extinction, explosion >N sigma, deadlock, runaway slope, agent oscillation) always-on; A/B run per level per seed]: Record EcologyIntentBatch bytes + apply-tick + pinned model/tier/seed to the plan log; REPLAY feeds recorded bands to guardrails (no LLM, bit-exact); DETERMINISTIC-NULL coasts on empty/last bands (token-free baseline). *Tradeoffs:* Determinism is genuinely weaker than the rejected pure-C++ LV sim: identical-seed LIVE runs diverge because the LLM's band choices vary; recovered only via record/replay of intent bytes + pinned model/tier. Same-seed variance must be reported as an envelope band, not a hard pass/fail — a real regression-testing regression.; The world is effectively ONLINE for authored evolution: without a capable on-device model, offline play falls back to indefinite coasting on the last bands, which drifts toward a static ecology (no new booms/busts/migrations) the longer the agent is absent. 'Alive off-screen' degrades gracefully but does degrade.; Believability near the player depends on the coarse->BT bias mapping being faithful; if the agent says 'boom' but the guardrail capped it at carrying capacity, the player may see fewer animals than the narrative implies. The digest must report guardrail-adjusted (not raw-authored) state back to the agent or it reasons on a fiction.; An LLM is a mediocre quantitative ecologist: it will propose implausible magnitudes, forget prior actions, and oscillate (grow/collapse/grow). The guardrail scaffold + memory + director_feedback mitigate this but cannot fully prevent dead worlds or bland equilibria — the honest verdict is HYBRID-REQUIRED, not LLM-alone.; Cost/latency force coarse granularity and slow ticks (~30 in-game min), so short-timescale ecological drama (a hunt failing, a pack starving over a day) is authored bluntly and only made vivid by the real-time BT layer, not by the agent — the agent gives narrative direction, not fine-grained dynamics.; Removing the deterministic LV math removes a self-balancing property: LV auto-balances via its own equations; here balance is an EMERGENT property of guardrails + agent judgement + migration, which is less mathematically guaranteed and needs calibrated watchdogs + soak testing per level to trust.; NOTABLE_INDIVIDUAL and persistent dormant records add ID-lifecycle complexity (ephemeral vs permanent) that the anonymous-cohort model otherwise avoids; a mis-scoped promotion leaks memory or dangles a quest reference (mitigated by giver-liveness preconditions from the parent spec).

## Persistence, Determinism-via-Recording, and Testability for the LLM-agent-authored Zone

The pivot changes what "determinism" even means: the world's evolution is now authored by persistent tool-using agents (Claude Code-style identity+memory+toolset+loop), so the recoverable, serializable substrate is no longer a C++ sim's state alone — it is (a) the thin authoritative near-player state store, (b) EACH agent's persistent memory, (c) every agent's in-flight plan, and (d) the append-only ledger of agent tool-calls. I make the tool-call ledger the single source of determinism: every agent action goes through ONE narrow C++ tool-dispatch choke point (`AgentToolBus`) that stamps `{seq, agent_id, sim_tick, wall_ns, tool, request_json, response_json, provider, model, tier, latency_ms, tokens_in, tokens_out, cost_micros}` and appends it to a per-session ledger before the mutation touches the store. Because C++ execution of an accepted tool-call is already deterministic, replay = serve the recorded response instead of calling the model, and the same C++ code path reproduces the world bit-for-bit. This is the FrugalGPT-style recordable-provider shim generalized from "LLM responses" to "all agent tool I/O," which is the load-bearing seam. Save = serialize the store (fixed-point, §6.2 firewall preserved) + a versioned blob per agent (memory summary, episodic ledger tail, grudges/goals) + the compiled in-flight ExecutionPlans + the PRNG states + the ledger tail since last checkpoint; a save is a snapshot-plus-ledger so it doubles as a replay seed. I keep the two-phase validate/apply invariant because it is now MORE critical: an agent authoring against a stale snapshot must degrade to a no-op, never a THROW (fatal on Darwin XRAY_EXCEPTIONS=0). To catch an agent authoring nonsense before players see it, I insert a deterministic C++ VALIDATOR (schema + reference-existence + range/quota/legality clamps, already speced) AND a cheap CRITIC pass: bounded structured sanity checks over the proposed delta (conservation, magnitude-vs-history, contradiction-with-active-plan, dead-world/runaway deltas) that run in pure C++/small-model on the coarse digest, quarantining a bad batch to feedback rather than applying it. Testability is a headless fast-forward harness driven entirely through the agent bridge: fixed-schema per-tick metrics, declarative temporal assertions evaluated in pure C++ (never LLM-judged), always-on failure watchdogs (dead-world, runaway, oscillation, incoherence, contradiction), provider-on/off A/B on the same seed+level, and per-session cost accounting. All of it rides the existing newline-framed Unix-socket bridge (verbs marshaled onto the sim thread), whose dispatch is a trivial verb switch I extend with new `agent.*` verbs. The acceptance gate for the whole subsystem is: record a LIVE session, replay it, assert byte-identical store snapshots at every checkpoint tick AND identical reconstructed agent-tree shape — proving the dynamic, non-deterministic agent world is deterministic under replay.

- **AgentToolBus (recordable choke point)** [deterministic C++; no model / on every agent tool invocation (write, memory op, spawn-subagent, world-read)]: Single C++ dispatcher every agent tool-call passes through. Stamps a ToolCallRecord {seq monotonic, agent_id, sim_tick, wall_ns, tool_name, request_json, response_json, provider, model, tier, latency_ms, tokens_in/out, cost_micros, validator_verdict, critic_verdict} and appends to the session ledger BEFORE the store mutation. In REPLAY mode it returns the recorded response instead of issuing a live model/tool call, keyed by (agent_id, sim_tick, tool_name, request_hash). This is the one seam that turns non-deterministic agents into deterministic input.
- **Snapshot = store + agent memory + in-flight plans + PRNG + ledger tail** [deterministic C++; fixed-point firewall / on user save, on ring-checkpoint every N ticks, and on bridge snap verb]: Versioned save via the engine's IWriter/IReader idiom. Blobs: {version, content_hash, sim_tick, all named-PRNG states, fixed-point store columns (RLE-skip dormant), dormant records, region statistical arrays, scar list, PER-AGENT {identity, scope, rolling summary, episodic ledger tail, grudges/goals, budget cursor}, compiled ExecutionPlans with per-op schedule offsets, and the ToolCall ledger tail since last checkpoint}. Restore rebuilds transient indices deterministically. Copy-on-write off the sim thread to avoid a stall. Same codepath serves save-game, LLM-context projection, and bridge replay.
- **Two-phase validator (stability-critical, unchanged invariant)** [deterministic C++; no model / phase 1 at ingest, phase 2 at plan-op drain tick]: Phase 1 ingest-validate a tool-call against the snapshot it was authored from (schema/type, reference existence, legality, range/quota clamp, intra-batch conflict last-writer-wins). Phase 2 apply-tick re-validate against CURRENT state at drain (entities may have died/materialized during the async agent call): a dangling ref degrades to region-aggregate retarget or drop-with-feedback, NEVER reaches a THROW. Rejections are values, logged, fed back to the agent as director_feedback.
- **Critic / nonsense-guard pass** [C++ rules primary; optional on-device SLM (llama.cpp-Metal) advisory / per accepted intent batch, before ExecutionPlan compile]: After validation, a bounded sanity pass over the PROPOSED coarse delta before apply: conservation check (population/economy sums conserved modulo logged births/deaths), magnitude-vs-history (delta > N sigma over the region's calibrated baseline = quarantine), contradiction-with-active-plan (verb reverses a committed intent inside its dwell window), and dead-world/runaway guards (batch that would zero or explode a region). Fails route to feedback+coast, not apply. Runs in pure C++ on metrics; optionally a cheap on-device SLM critic on the digest for narrative-coherence only, its verdict advisory and recorded.
- **Headless fast-forward soak (zonesoak.py over the bridge)** [harness deterministic; model tier depends on run mode / CI-style and manual; bridge-driven]: Ticks the sim without a renderer (already committed capability) for in-game days, in LIVE / REPLAY / DETERMINISTIC-NULL modes. Emits a fixed-schema MetricRecord per tick to a ring buffer (~28 in-game hours at 1 Hz) + NDJSON sink for multi-day runs. Returns a pass/fail health report against calibrated baselines.
- **Behavioral assertions + always-on watchdogs** [deterministic C++/Python; never LLM / watchdogs every tick; assertions polled by bridge]: Declarative temporal predicates (hold/within/eventually/never/converges) over the metric window and named entity queries, evaluated in pure deterministic C++/Python so an LLM never judges its own Zone. Always-on watchdogs: dead-world (no state delta across K ticks / unintended pop->0), runaway (pop/money > N sigma), oscillation (intent flip-flop rate, min-dwell violated), incoherence (rejected-intent ratio, contradiction-with-prior-plan rate). Baselines from a DETERMINISTIC-NULL calibration soak per level.
- **Provider-on/off A/B + cost accounting** [A/B spans null vs frontier+SLM ladder / CI A/B jobs; budget asserted per soak]: Run the same seed + same imported level under provider-off (coast on deterministic shadow) vs provider-on, diff metric trajectories, and assert the agents ADD liveliness (event variety, faction/territory flux) WITHOUT breaking a guardrail the null run held. Cost ledger accumulates tokens/cost_micros per agent per session from the ToolCall records; a regression test asserts a scenario stays under its LTX budget ceiling and that degradation fired in the correct skip order when throttled.
- **Replay determinism gate** [REPLAY serves recorded responses; zero live calls / acceptance gate; runs headless in CI-style bridge scripts]: Record a LIVE session's ToolCall ledger, then REPLAY serving recorded responses, and assert byte-identical store snapshots at each checkpoint tick AND identical reconstructed agent-tree shape (which agents existed, which subagents spawned, model/tier per decision — all pure functions of snapshot+seed+recorded responses). This is the single acceptance gate for the subsystem.

*Tradeoffs:* Replay fidelity depends on the C++ execution path being 100% deterministic given recorded responses; ANY nondeterminism leak (float in persisted state, hash-map iteration order, thread-order reduction) silently breaks byte-identity. The fixed-point firewall + id-ordered reductions must be enforced by hard assertions, and any regression is caught only by the replay gate — which makes that gate load-bearing and slow.; The ledger grows with every tool-call; a 100-hour campaign accumulates a large append-only log. Mitigation is snapshot-plus-ledger-tail (truncate ledger at each checkpoint) but that means a save is only replayable forward from its last checkpoint, not from t0 — full-campaign replay requires retaining all checkpoints, a storage cost.; Recording captures request+response bytes including model outputs; replaying a save authored under Opus while the live model has since changed produces a DIFFERENT live run — replay is faithful only to the recorded bytes, so cross-version reproduction requires pinning model+tier+seed in the record, and a live re-run is explicitly NOT reproducible.; The critic pass adds latency/cost to the authoring path and can itself be wrong: too strict and it quarantines legitimate emergent narrative (a real faction collapse looks like a runaway delta), too loose and nonsense reaches players. Its thresholds are empirical and per-level-calibrated, an ongoing tuning burden.; Serializing agent memory as first-class state couples save-format stability to agent prompt/memory schema evolution; changing an agent's memory structure between versions risks unloadable saves unless every agent blob is strictly versioned and migrated.; Determinism is weaker than the pre-pivot pure-C++ sim: LIVE runs are only reproducible via recording, so bug reports from players are only actionable if recording was on. Ship with recording-on-by-default for at least a ring of recent ticks (a flight recorder) to keep field bugs replayable, accepting the disk/perf cost.; A/B liveliness assertions are inherently fuzzy — 'adds liveliness without breaking guardrails' is a soft metric; same-seed LIVE variance must be reported as an envelope band, not a hard pass/fail, which weakens CI signal for the exact feature (LLM authorship) that most needs it.
